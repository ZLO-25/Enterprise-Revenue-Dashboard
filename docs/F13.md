# 大師持股（13F）頁（13f/）

13F 是美國大型投資機構每季向 SEC 申報的持股清單。本頁追 9 位長期投資人的最新持股與每季變化，個股頁多一行「13F 參考」。
**只是參考資訊**：不進論點卡燈號、估值門檻、每日檢查（`docs/SCHEDULE_PROMPT.md` 不改）。

```
data/13f/config.json（經理人、組別、tracked 公司對照表；Claude 維護）
        │
        ▼  GitHub Actions：f13-quarterly（每天一班，0 token）
tools/f13_fetch.py --check   SEC submissions 有沒有新申報？沒有 → 約 10 秒結束
tools/f13_fetch.py           9 位 × 最近 8 季（多讀 1 季算變化）→ data/13f/<id>.json、latest.json、by-company.json
tools/f13_check.py           總值／列數／CUSIP 對照 → 有 ✗ 或「待確認」開 issue「13F 大師持股檢查：有問題」
        │
        ▼
13f/ 頁與個股頁那一行：打開時才讀 data/13f（不必重建網站）；沒有檔案顯示「資料尚未抓取」
```

## 資料來源與規則
- SEC EDGAR：`data.sec.gov/submissions/CIK….json`（申報清單）、`www.sec.gov/Archives/edgar/data/<cik>/<acc>/index.json`（找檔名）、`primary_doc.xml`（封面與摘要）、持股表 XML（檔名不固定）。User-Agent 同 `tools/sec_feed.py`，每次請求間隔 ≥ 0.15 秒，失敗重試 3 次。
- `value` 單位：2023-01-03 以後申報是元，之前是千元（程式依申報日換成元）。
- 同 CUSIP＋putCall＋SH/PRN 的列合併（Berkshire 同一檔分多列）；`rawRows`＝合併前列數，對 `tableEntryTotal`；`sumValue`＝自己加總，對 `tableValueTotal`（容許 0.5% 或 1 千元）。
- 修正版：`RESTATEMENT` 整份取代；`NEW HOLDINGS` 加到原始上；多份依申報順序套用。`amended`、`amendments[]` 記錄套了哪些。
- 本季變化（new／add／reduce／exit／same）比股數，對上一個日曆季；上一季沒申報、只有 13F-NT 或季別不連續 → 變化留空並寫 `chgNote`（不猜）。出清的列保留（value 0，`prev`＝上季股數）。
- 13F-NT：沒有持股表。`config` 的 `ciks` 列了接手申報人（Pershing：主 CIK 0001336528、接手 0002026053）時，該季改用接手申報人的 13F-HR，卡片標明並連到主申報人的 NT；兩邊都有 13F-HR 以主 CIK 為準並在 check 報出。沒有接手持股表的季顯示「持股待確認」。
- 寫檔：每位經理人各自成功才覆蓋自己的舊檔；失敗那位保留舊檔，整次 exit 1（紅燈）。

## tracked 對照表（本站公司 ↔ CUSIP）
- `tracked.<代號>.cusips`：只有在這裡的 CUSIP 才算本站公司（頁面與 `by-company.json` 不用名稱猜）。`issuerKeys` 是 nameOfIssuer 的大寫片段，只用來「核對」與「回報」。
- `cusips` 是 `[]`＝尚未確認：頁面標「待確認」、不判斷有沒有人持有。初始只填了申報檔裡親眼看到的（Apple、Alphabet 兩個類別）。
- 確認方式：抓完後 `python3 tools/f13_check.py` 會列「待確認：… 持有「<名稱>」CUSIP … 不在對照表」。Claude 確認名稱確實是該公司（看申報頁的原文）後，把 CUSIP 填進 config，下一次抓取就會標上 `code`（或手動觸發 f13-quarterly，force）。
- 台股、韓股本股不在 13F：`notCovered` 列出（三星、台達電、萬潤、國巨），個股頁那一行顯示「13F 不涵蓋」。台積電用 ADR（TAIWAN SEMICONDUCTOR）。

## 頁面
- `13f/`：組別分頁籤 → 經理人卡片（最新一季、前 10 大、季別下拉最近 8 季、看全部）→「本站公司 × 大師」對照表。範本：`templates/f13.frag.html`；經理人說明（`why`）標「教學」；數字標「書面（SEC 13F）」。
- 個股頁：`assets/f13line.js`（併入共用的 LONGTERM，三種版型都有），放在檢查表（`#buffett`）之後：「13F 參考（2026Q3）：N 位大師持有；本季 加碼 a、減碼 b、新增 c、出清 d → 看大師持股」。讀不到 `by-company.json`（尚未抓取）就不顯示；`notCovered` 的公司顯示「13F 不涵蓋」。

## 13F 的限制（頁面也寫了）
- 落後：季末後最多 45 天才公開。
- 只有多單與美國 13(f) 證券，不含空單、現金、多數債券、美國以外掛牌的股票。
- 可以申請保密延後揭露（申報檔 `isConfidentialOmitted`；標示時卡片會寫）。
- 經理人買賣的理由、成本、停損，13F 都看不到；不是買賣訊號。

## 有問題時（issue「13F 大師持股檢查：有問題」）
1. 讀 issue 內文（`f13_check.py` 的輸出）。
2. `✗ … 對不上 tableValueTotal／tableEntryTotal`：到該季申報頁看原始檔，確認是申報人自己的錯、解析漏列，還是單位問題；修 `tools/f13_fetch.py` 並補測試（`tools/tests/test_f13.py`），不要手改 `data/13f`。
3. `待確認：… 不在 tracked 對照表`：確認是同一家公司後填 `data/13f/config.json` 的 `cusips`；不是就調整 `issuerKeys`。
4. `待確認：… 持股改由 … 申報`（13F-NT）：正常現象；若接手申報人有 13F-HR 但還沒列在 `ciks`，補上它的 CIK。
5. 處理完手動觸發 f13-quarterly（force），確認 issue 不再出現後關閉。
