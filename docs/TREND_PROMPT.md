# 世界科技趨勢月報（排程：每月 2 日 台北 08:47）

> 這份就是排程的指令全文。排程本身只是一句「照 docs/TREND_PROMPT.md 做」，所以改這份＝改排程，不用重建排程。
> 目標：每月用同一套方法看一次世界科技趨勢，判斷對網站追蹤公司的影響，並且**每期都回頭對帳上期預測**。

```
上期月報＋預測帳本 ──┐
                     ├─► 搜尋本月大事（6–8 次）─► 5 個主題逐一：上期判斷 → 新證據 → 維持／修正
skill 趨勢方法 ──────┘                                   │
                                                         ▼
                              寫月報 reports/trend/<YYYY-MM>_世界趨勢.md
                              更新帳本 reports/trend/LEDGER.md（對帳＋新增預測）
                                                         │
                                                         ▼
                                          commit＋push main，回報 8–12 行
```

## 晚跑或補跑（額度用完時）
- 每月 2 日沒成功時，每日排程會在 3 日之後補觸發一次（3 天內不重複）。晚跑時期別仍是**應出刊的月份**（例：12/9 補跑仍是 2026-12 期），搜尋範圍改成「上一期月報日期到今天」。
- 已經有本月的 `reports/trend/<YYYY-MM>_世界趨勢.md` 就**不重寫**，回報「本期已存在」後結束。
- 整個月都沒跑成（上一期缺）：不補寫舊月份，本期對帳範圍延長到上一份存在的月報，月報開頭寫一行「上期缺刊」。

## 步驟（照順序）
1. 取得 repo `ZLO-25/Enterprise-Revenue-Dashboard` 最新 main。不能讀寫 repo：回報原因並結束。
2. 讀 `CLAUDE.md`、`.claude/skills/long-term-company-analysis/SKILL.md` 第 1、5、6 節、`trend.md` 全文。**不讀**任何作者觀點檔（那些不在 repo，也不要去找）。
3. 讀 `reports/trend/LEDGER.md` 和最新一期月報（沒有就是第一期：跳過對帳，帳本從本期開始）。
4. 對帳：帳本裡到期或已有結果的預測，逐條標 ✓／✗／部分／未到期，附證據來源（公司公告、主管機關、大型通訊社）。錯的寫一句「錯在哪個思考步驟」。
5. 搜尋：一般模式，同一回合送出，總共 6–8 次就停。固定題目：
   ① AI 算力供需（雲端 CAPEX、GPU／ASIC 交期、算力租價）
   ② AI 應用變現（模型公司營收、企業採用、定價）
   ③ 半導體週期（記憶體報價、晶圓代工稼動、設備訂單）
   ④ 能源與電力（資料中心用電、電網、燃氣渦輪與核能）
   ⑤ 監管與地緣（出口管制、關稅、反壟斷）
   ⑥ 本月最大的一件事（不在上面五類的）
   只取過去約 35 天的消息。
6. 寫月報（格式見下）。每一句都標來源類型：書面（公司公告、申報）、口頭（法說會，附逐字稿連結）、媒體（屬「待確定」）、觀點（Claude 判斷）。
7. 新預測寫進帳本：每條要有方向、時間點、信心、檢驗方式。時程與量級照 trend.md 的「預測校正」表打折，並寫出用了哪一列。
8. 只改 `reports/trend/` 底下的檔案。commit「世界趨勢月報 <YYYY-MM>」，push main（遇到衝突就 pull 後重推，最多 3 次）。**不要**改網站資料、skill 或其他文件。

9. **記 token**（最後一步）：`get_session`（不帶 id）讀 `external_metadata.usage`，執行 `python3 tools/daily.py tokens add trend --session <id> --model <model> --input <input_tokens> --cache-read <cache_read_tokens> --cache-write <cache_write_tokens> --output <output_tokens> --cost <cost_usd>`，再 `python3 tools/daily.py tokens report`，commit「token 用量」並 push（這是第 8 步「只改 reports/trend/」唯一的例外：`data/token-usage.json`、`reports/token-usage.md`）。

## 月報格式
```
# 世界科技趨勢 <YYYY-MM>
一句話重述本期要回答的問題。

## 本期 3 件大事
| 事件 | 為什麼重要 | 影響哪幾家追蹤公司 ↑↓ | 來源 |

## 主題追蹤（5 個主題各一段）
上期判斷 → 本期新證據 → 維持／修正（附 ASCII 因果圖，至少 2 張）

## 預測帳本對帳（上期與更早到期的）
## 本期新預測（方向＋時程＋信心，三段分開）
## 對追蹤公司的含意（只列有變化的，最多 8 家）
## 待確認／待確定清單
```
- 用 trend.md 的「真趨勢五問」檢查一個本期最熱的主題。
- 只寫網站追蹤的公司（data/companies.json 中 enabled 的）。
- 篇幅：2,000–3,500 字。繁體中文、白話、能拿去教別人。
- 非投資建議，文末寫一行。

## 帳本格式（reports/trend/LEDGER.md）
```
| 編號 | 立帳月 | 預測 | 時間點 | 信心 | 校正依據 | 檢驗方式 | 結果 | 對帳月 | 錯在哪 |
```
編號格式 T<YYMM>-<n>。只加不刪，結果欄更新。

## 資料誠實規則（摘要，完整見 CLAUDE.md）
- 不估計、不內插、不從記憶補數字；找不到寫「待確認：<什麼>，原因」。
- 只有媒體報導、公司未證實的：標「待確定」。

## 回報格式
```
世界科技趨勢月報 <YYYY-MM>：完成／部分完成
· 本期一句話結論
· 3 件大事（各一行）
· 對帳：✓ x／✗ y／部分 z／未到期 w
· 修正了哪個主題的判斷
· 月報檔案路徑與 commit
```

提醒：趨勢是找「能力圈」的材料，幫你決定哪些生意值得花時間看懂，不是買賣訊號（觀念意譯，見 docs/BUFFETT_MUNGER.md）。
