# 總經儀表板（macro/）

目標：個股頁回答「這家公司好不好、貴不貴」，這一頁回答「現在整體景氣在循環的哪一段」。
指標清單照愛榭克（Izaax）《景氣循環投資》書裡用到的美國經濟數據整理，再加上台灣景氣燈號與「AI 資本支出鏈」。

```
data/macro/config.json（指標清單、四階段對照表、外部連結；Claude 維護）
        │
        ├─▶ GitHub Actions：macro-weekly（台北週六、週三清晨；不經過 Claude）
        │       tools/macro_fetch.py
        │         ├ 美國：FRED 公開 CSV（免金鑰）
        │         └ 台灣：政府資料開放平臺的國發會官方檔（景氣指標及燈號 6099、採購經理人指數 6100）
        │       └─▶ data/macro/latest.json（只有 Actions 會寫；年增率與方向燈都在這裡算好）
        │
        └─▶ tools/build.py
                ├ tools/capex_chain.py：用各公司財報加總「AI 資本支出鏈」（建置時算，不存檔）
                └─▶ macro/index.html（templates/macro.frag.html；打開頁面時才讀 latest.json，所以每週更新不必重建網站）
```

## 資料誠實

- 數字只由 Actions 寫入，Claude 不手填、不修改 `data/macro/latest.json`。
- 某條序列抓不到：沿用上一次的資料，並在 `unavailable` 寫「待確認：」；從沒抓到過就不顯示。不估計、不內插。
- 沒有免費官方資料檔的指標（美國 ISM、經濟諮商局消費者信心、巴菲特指標與 Shiller 本益比）不抓，只在「外部網站」給連結。
- 書的內容來自讀者筆記，不是原書原文：頁面一律標「整理，不是原話」，不用引號假裝引述。筆記連結在 `config.json` 的 `about.notes`。
- 這一頁**不判定現在是哪個階段**，只把數據和書裡的判讀並排。

## 內容分哪幾種

| 標籤 | 意思 | 例子 |
|---|---|---|
| 書面 | 官方統計或公司財報的數字 | 每一列的最新值、台灣燈號、各公司資本支出 |
| 公式 | 用書面數字照固定公式算的 | 年增率、方向燈、四家資本支出合計 |
| 整理，不是原話 | 讀者筆記記錄的書中判讀 | 「書裡怎麼看」、四個階段對照表 |
| 觀點 | Claude 的說明 | 「怎麼讀」 |

## 方向燈（唯一計算處：`tools/macro_fetch.py` 的 `stats()`）

```
半年變動 = 最新值 − 半年前的值（月資料往前 6 筆、季資料往前 2 筆）
平常幅度 = 過去 10 年每一個半年變動的 MAD × 1.4826（用中位數算，不怕 2020 年疫情那種極端值）
z = 半年變動 ÷ 平常幅度
    z 往壞的方向 ≥ 1 → 轉差；往好的方向 ≥ 1 → 轉好；其餘 → 持平
```

- 「壞的方向」寫在每條指標的 `bad`（`up`／`down`）；空白代表沒有固定好壞方向（利率、油價、美元、儲蓄率…），不亮燈。
- 方向燈只說「最近半年明顯在變」，不是買賣訊號。門檻（1 倍）是分析師草稿，ZL 可改：`config.json` 的 `light.threshold`。

### 愛榭克的思考邏輯從哪裡來

他部落格（izaax.net）的近期文章要登入才能讀，**沒有讀、也不引用**。能用的公開資料分三類，寫在 `about.sources`，每一則 `concepts[].srcs` 都要指到這裡（測試會擋）：

| 類別（`kind`） | 可信度 | 例子 |
|---|---|---|
| 書摘（本人著作）、本人文章 | 最高：他自己的文字 | Smart 智富刊出的《景氣循環投資》《道瓊三萬點》節錄、關鍵評論網 2020 的文章 |
| 書摘（記者／編輯整理） | 中：別人摘他的書 | 「連續 5 季下修」「跌幅超過 10%」兩個衰退確認門檻出自這裡 |
| 聽眾筆記、讀書筆記、書評 | 較低：可能記錯或簡化 | 2020、2021、2025 分享會的筆記 |
| 教學 | 本站自己的說明 | 名詞解釋、常見誤判、`concepts[].teach` |

規矩不變：全部是整理，不是原話；不用引號假裝引述；筆記沒有的門檻不補；年代較早的說法只當方法、不當現在的結論。
想補新的來源（例如 ZL 貼了登入後的文章）：在 `about.sources` 加一筆，再改 `concepts`。

### 觀念提醒（`reminders`）

條件寫在 `config.json`，**成立與否由 `tools/macro_fetch.py` 的 `eval_cond()` 判斷**（頁面只把成立的排出來）。資料缺的條件一律算不成立。

| 條件 | 意思 |
|---|---|
| `{"key":k,"light":"worse"}` | 那個指標現在的燈 |
| `{"key":k,"lt":x}`／`{"gt":x}` | 最新值小於／大於 x |
| `{"key":k,"downRun":n}`／`{"upRun":n}` | 連續下降／上升至少 n 期（那條指標要有 `"run": true`） |
| `{"key":k,"baseHi":85}`／`{"baseLo":15}` | 去年同期的年增率在十年裡的百分位（基期偏高／偏低） |
| `{"key":k,"pctHi":90}`／`{"pctLo":10}` | 最新值在十年裡的百分位 |
| `{"count":{"keys":[…],"light":"worse","min":a,"max":b}}` | 幾個指標裡亮那種燈的個數 |
| `{"boom":{"min":a,"max":b}}` | 七大指標現在亮幾項 |
| `{"tw":"紅"}` | 台灣景氣燈號 |
| `{"all":[…]}`、`{"any":[…]}`、`{"not":…}` | 組合 |

`level`：`watch`（留意，紅邊）或 `calm`（觀念，藍邊）。每條提醒要指到一則 `concept`。

### 警訊計數（`score`）

- `light_series()` 用和方向燈同一個公式，把每條序列歷史上每一筆的燈算出來（只用那一筆以前的資料，有測試確認沒有偷看未來）。
- `score_series()`：每個月，七大指標（`phases` 裡 `boom` 的 7 個 `checks`）有幾項亮轉差；一項裡任何一條轉差就算。季資料與公布較慢的資料，沿用最近 4 個月內的最新一筆。
- `score_table()`：每次衰退開始前 12 個月最多亮幾項、亮 N 項的月份各落在哪種時期。
- 限制寫在頁面上：用的是今天修正後的資料、照資料所屬月份排，沒有扣掉公布落後。
- **改門檻**：`config.json` 的 `light.threshold`（預設 1）、`light.years`（預設 10）。push 後整段重算，直接看對照表有沒有變好。

### 其他公式

| 東西 | 算法 | 在哪 |
|---|---|---|
| 三個月年率（`show: "ann3"`） | (現在 ÷ 三個月前) ^ 4 − 1 | `to_ann()` |
| 兩條 FRED 相除（`ratio`） | 每一季取分子在那一季的最後一筆 ÷ 分母 × `mult` | `ratio_points()` |
| 兩條本頁序列相減（`diff`） | 同一個月都有值才算 | `diff_points()` |
| 基期 | 去年同期的年增率，以及它在十年年增率裡的百分位 | `base_effect()` |
| 現在的燈從哪一筆開始、之前是什麼 | `stats()` 的 `lightSince`／`lightPrev` | 頁面「最近換燈」 |
| 台灣各燈號的分數範圍 | 官方檔最近十年「分數＋燈號」的配對 | `score_ranges()` |

## 長期運作（壞了怎麼知道、怎麼修）

```
macro-weekly 每次抓完
   ├─ 哪條序列的「資料截至日」離今天太久？（日 14 天、週 28 天、月 110 天、季 290 天；可用 maxLag 個別放寬）
   ├─ 設定檔裡所有連結連一次：404／410 才算失效（403、逾時是擋機器人）
   └─ 寫進 latest.json 的 health、links、unavailable
                │
                ▼
tools/status.py（daily-prep 每天跑）→ 系統健康頁「總經資料」
   綠：都正常　黃：有停更、抓不到或 404　紅（開 issue、寄信）：資料檔超過 10 天沒更新，或一半以上抓不到
```

| 看到什麼 | 多半是什麼原因 | 怎麼處理 |
|---|---|---|
| 某條標「停更？」 | FRED 停掉那條序列或換代號；美國政府關門延後公布 | 到 FRED 查那個代號。延後公布：等。停更：在 `config.json` 換代號或刪掉那一條（對照表與提醒用到它的地方測試會提醒） |
| 「待確認：…這次抓取失敗」 | 網路或 FRED 暫時問題 | 下一班會自己重抓；連續兩週都失敗再查 |
| 台灣整區待確認 | 政府資料開放平臺改了檔名或欄名 | Actions 手動跑 macro-weekly 勾 probe，看檔名與表頭，改 `tw.files[].match` 或 `tw.series[].col`（欄名可以只寫開頭） |
| 連結旁出現「打不開」 | 對方網站改版 | 換新網址或刪掉 |
| 健康頁「總經資料」紅燈 | 排程沒跑或整個來源壞了 | 手動執行 macro-weekly（勾 force）看 log |
| 想加新指標 | — | 加進 `config.json`，先在分支 push：macro-weekly 會在分支上跑，log 會印每條有沒有抓到，確認後再合併 |

排程：GitHub 的定時排程常晚到或漏跑，所以除了每週幾班，`daily-prep` 每天也會叫醒 `macro-weekly` 一次；五天內抓過就約 10 秒結束。

## 每天更新、每週摘要、首頁的 VIX（2026-11-22）

```
平日每天   daily-prep 叫醒 macro-weekly → 18 小時內沒抓過就重抓（STALE_HOURS）→ latest.json
           prices-daily 的 tools/vix_update.py → data/market/vix.json → 首頁「市場情緒」那一行
每週日     排程照 docs/WEEKLY_NEWS_PROMPT.md 步驟 6c 跑 python3 tools/daily.py macro
           （tools/macro_brief.py：把現在的 latest.json 和 git 裡一週前那一版相比）→ 回報「總經」段
```

- **為什麼有兩個 VIX**：總經儀表板的 VIX 來自 FRED（慢一個交易日左右），用來算方向燈與觀念提醒；首頁那一行要「今天早上就看到昨晚收盤」，所以另外抓 Cboe 官方每日檔與 Yahoo ^VIX，取最新一筆比較新的那個，兩邊都有的最近一天互相核對（差超過 1% 記待確認）。兩處各自標日期與來源。
- **只收收盤、一天一次**：VIX 是情緒，照「先基本面、再資金面」排在最後；不做盤中。Yahoo 在美股盤中會給盤中值，`drop_unfinished()` 會把還沒收盤那一天拿掉。
- **區間門檻**（20 以下平靜、30 以上很緊張）是經驗分界，寫在 `tools/vix_update.py` 的 `ZONES`，首頁標「教學」，不是買賣訊號。
- **壞了怎麼查**：Actions 手動跑 prices-daily 看「VIX 收盤」那一步的 log（每個來源抓到幾筆、最新日期、核對結果）；或在本機以外的環境跑 `python3 tools/vix_update.py --probe`。晚上那一班的落後檢查會在最新一筆超過 6 天時亮紅燈。
- **每週摘要不解讀**：`tools/macro_brief.py` 只列差異（換燈、提醒新增與消失、警訊計數、台灣燈號、資料健康），不寫買賣建議、不判定景氣階段（測試會擋這些字）。

## 美元・利率・通膨對照圖（總覽區下方，2026-11-24）

ZL 想在網站上看到和 TradingView 一樣的疊圖（DXY 日 K＋FEDFUNDS＋CPI 年增率，原油與 SPY 隱藏）。

```
Yahoo：DX-Y.NYB（開高低收）、SPY（收盤） ─┐
FRED：FEDFUNDS、DFEDTAR／L／U、CPIAUCSL、   ├─ tools/macro_overlay.py（macro-weekly 同一班，在 macro_fetch 之後）
      DCOILWTICO、DGS2、DFII10              ─┘        │
```

- 為什麼另一個檔：latest.json 的日資料只留每月最後一筆（算方向燈用），K 棒要每天的資料。
- 左軸美元指數 K 棒；右軸 %（有效利率、CPI 年增率、目標區間上下限虛線、2 年期、實質利率）；原油、SPY 各用自己看不見的軸。預設顯示前三條，勾選記在 localStorage `erd-mxo-on`，期間 `erd-mxo-range`（預設 3 年）。
