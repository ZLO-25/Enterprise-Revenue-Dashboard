# 轉機／早期型（例：TSLA 現階段、RKLB、GEV*、早期 PLTR）
*歸類以網站論點卡為準。

作者對這類公司特別看（依 TSLA、PLTR 早期、SE、Intel 筆記）：
1. 用需求指標判斷是供給問題還是需求問題（交車存貨天數）。
2. 本業毛利率能否撐住降價（扣除碳權等一次性）。
3. 新業務里程碑與時程（FSD 版本、Robotaxi 城市與車隊、Optimus 產量）。
4. 現金水位與燒錢速度、調整後 EBITDA 轉正順序（SE 熊市）。
5. 砍掉無效擴張是正面訊號。
6. 第二引擎是否已能自給（TSLA 儲能，作者最準的判斷）。
6b. 量價拆分：交車成長 − 營收成長 ≈ 降價幅度；降價幅度反推單位成本。
7. 揭露口徑改變 = 營運重心改變。
8. 計畫容錯度：「要考 120 分才及格」的計畫，一延誤就連鎖出事（Intel 四年五節點）。

作者在這類公司常犯的錯（要修正，這類最嚴重）：
- 時程一再跟著創辦人延誤 → 時程延後 6–12 個月（作者已自打折時以作者版為準）。
- **Musk 體系數量，順序固定**：① 寫現況實數（例：車隊 600 台）② 作者版＝現況 × 合理增幅，管理層自己說要慢就照慢 ③ 校正版 ≤ 作者版，不得更高 ④ 作者已給信心度或已打折的，校正只調信心，不再折數量。÷3 只用在作者直接引用 Musk 目標時（事後驗證：新產品數量 5 條全錯，實績是目標的 0–57%）。既有車款年度量預設不高於去年，除非存貨天數下降（車輛本業 7 條方向判斷全錯、都偏樂觀：交車 2024 實際 −1.1%、2025 −8.6%）；作者自己推的單季交車可照收。（事後驗證 Musk 體系 20 條命中 33%、TSLA 27 條 41%；照收 Musk 說法的 18 條命中 33%。）
- **轉機型的季度好壞＝新業務里程碑有沒有前進**；本業數字好只寫成「現有業務不錯」。
- 氣氛最好時最容易採信管理層；正負敘事比超過 3:1 再打折。
- 單季毛利率回升不外推；政策截止前（補貼、關稅）的存貨天數不可用。
- 把管理層路線圖當進度證據 → 只認已出貨、已認列的。
- 訂單積壓當成永久需求、相信價格戰會收斂 → 寫出反方情境。
- 信念壓過估值紀律（「永遠不押注馬斯克失敗」）→ 必寫「如果我錯了，會先看到什麼」。

估值：多數時候本益比無意義；用情境（樂觀／基準／悲觀）列出各自需要的里程碑，並寫明「目前價格隱含哪個情境」。
