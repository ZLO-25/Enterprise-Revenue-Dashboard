# 加入每月本益比與 forward PE：完成報告（2026-11-12）

## 我理解的目標與問題
**目標**：每家公司的網頁都能看到「每個月月底的本益比（P/E）」，並加上「預估本益比（forward P/E）」。
**問題**：財報網站只有財報數字，沒有股價；而本益比要「當時投資人看得到的 EPS」，所以不能只用事後整理好的年度 EPS，還必須知道每一季 EPS 是哪一天第一次公開的。

```
本益比 ＝ 月底收盤價 ÷ 月底當天「已公布」的最近 4 季 EPS 加總
                          │
         EPS 要等財報公布日（rd）才算數
         ┌──────────────────────────────────────────┐
  季底 ──┤ 公布前：這一季還不能用 → 用前 4 季            │
  財報日 ─┤ 公布後：這一季算進去，最舊那一季拿掉           │
         └──────────────────────────────────────────┘
```

## Forward PE（預估本益比）怎麼算
```
預估本益比 ＝ 月底收盤價 ÷ NTM EPS

NTM（未來 12 個月 EPS）＝ w × 今年度預估 EPS ＋ (1 − w) × 下年度預估 EPS
   w ＝ 今年度還剩幾天 ÷ 365（最多 1）

  今年度結束日
  ──────┬─────────────────────┬─────────▶ 時間
  月底  │←── 剩 d 天 ──→│  下年度 (365−d 天)
        └ 這段用今年度 EPS    └ 這段用下年度 EPS
```
例：AAPL 月底收盤 344.63，今年度 EPS 預估 8、下年度 9、會計年度結束還剩 330 天：
w = 330/365 = 0.904，NTM = 0.904×8 + 0.096×9 = 8.096，預估本益比 = 344.63 ÷ 8.096 = **42.6×**（我用測試資料實測，畫面與手算一致；測試資料沒有提交）。

規則：
- 一律標「分析師預估」，美股多為調整後（non-GAAP）EPS，不能和歷史本益比直接相減。
- 分析師少於 3 位標「預估人數少」；NTM ≤ 0 顯示「預估虧損，不適用」。
- 只存每月月底後 10 天內的快照，**不回填**。10 月底的快照已過期限，所以第一筆是 2026-11 月底（12 月初產生）。現在網頁顯示「累積中」。

## 財報公布日（rd）怎麼取得（和原計畫的差異）
| 公司 | 來源 | 標記 |
|---|---|---|
| 美股（AAPL、MSFT、NVDA、MU、TSLA、ANET、PLTR、AMZN、SPCX） | SEC 申報日（10-Q／10-K 的 XBRL「filed」，且須在季底後 5～100 天） | `f` 或 `p` |
| 台積電 | 證交所 BWIBBU「財報年/季」第一次換季的日期；最新一季 3Q26 用 2026-10-15 新聞稿 dateline | `t`／`p` |
| 台達電 | 證交所 BWIBBU 換季日 | `t` |
| 三星 | 公司財報法說會日期 | `c` |

差異與限制：
- 原計畫優先用 8-K 新聞稿日；SEC 擋住 GitHub 機器和讀網頁工具（403／robots），所以改用 XBRL 申報日，通常比新聞稿晚幾天，偏保守。
- 台股的證交所換季日通常比公司公告晚一個交易日以上。例：台積電 2026-10 月底，證交所官方本益比 27.47 還沒換 3Q26，我們 24.1 已算入 3Q26（公司 10/15 已公告），差 12.3%。這是唯一超過 2% 的月份，其餘台積電 113 個月、台達電 80 個月差都在 0.6% 以內。
- 沒有取得公布日的季度一律留 `null`（不推算），列在下面「待確認」。
