# 蘋果 Apple（AAPL）資料來源與更新步驟

- 資料檔：`data/aapl.json`（schema `v1`）　頁面：`/aapl/`　模板：`templates/generic.frag.html`（通用模板）
- 單位：**百萬美元**（`rev`、`gp`、`opInc`、`ni`、`ocf`、`capex`、`fcf`）；每股數字（`eps`、`dps`）為美元，**已換算成現在的股數基準**（見下）。
- CIK：`0000320193`。頻率：每季。財報日約在 1、5、7、10 月最後一週（美股收盤後）。
- 排程：週二至週六 08:30（台北）每日檢查（見 docs/SCHEDULE_PROMPT.md；公布日隔天先做「快報」，再「補完」「核對」）。只補「上次資料之後」的新期間，舊數字不重抓；沒有新財報的月份只檢查事件與公布日；沒有實質變動就不 commit。

## 會計年度與季度標籤

蘋果的會計年度在 **9 月最後一個星期六** 結束（52／53 週制），**季度標籤用公司自己的會計年度**：

```
FY2027 = 2026/9/27 ─ 2027/9/25（約）
  1Q27 = 2026/10–12   （2027/1 底公布，含聖誕季，全年最大一季）
  2Q27 = 2027/1–3     （2027/4 底或 5 月初公布）
  3Q27 = 2027/4–6     （2027/7 底公布）
  4Q27 = 2027/7–9     （2027/10 底或 11 月初公布，含全年）
```

`annual` 的鍵 `"2026"` 就是 FY2026（2025/9/28–2026/9/26）。

## 期間

1Q09（FY2009 第一季，2008/10–12）–最新一季。XBRL 的 FY2008 只有第三季單季與全年，缺第一、二季，第四季推不出來，所以從 FY2009 開始；FY2007 以前沒有 XBRL。

## 來源（依可信度）

1. **SEC EDGAR XBRL**：`https://data.sec.gov/api/xbrl/companyconcept/CIK0000320193/us-gaap/{概念}.json`（WebFetch 讀得到；容器 curl 會被擋）。讀法：每個 (start, end) 取最近一次申報（filed 最晚）的值，只看 form 10-K／10-Q。
2. **財報新聞稿（8-K 附件 99.1）**：檔名慣例 `a8-kex991q{季}{季末日YYYYMMDD}.htm`，例 `https://www.sec.gov/Archives/edgar/data/320193/000032019325000077/a8-kex991q4202509272025.htm`。accession 號碼要用 WebSearch 找（搜尋「sec.gov Archives 320193 a8-kex991q4 2026」）。損益表、現金流量表都在這頁。
3. 蘋果新聞中心 `https://www.apple.com/newsroom/`（股票分割、股利公告；新聞稿正文不含報表數字）。
4. 可信媒體：**只用於事件時間軸**；公司未證實的一律 `unc:1`。

## 欄位定義（`quarters[]`）

| 欄位 | XBRL 概念與口徑 |
| --- | --- |
| `rev` | FY2018 起 `RevenueFromContractWithCustomerExcludingAssessedTax`；FY2017 以前 `SalesRevenueNet`（重疊年度數字相同） |
| `gp`、`gm` | `GrossProfit`（蘋果稱 Gross margin 金額） |
| `opInc`、`om` | `OperatingIncomeLoss` |
| `ni` | `NetIncomeLoss` |
| `eps` | `EarningsPerShareDiluted`，再依申報日換算分割（見下）；第四季見下 |
| `ocf` | `NetCashProvidedByUsedInOperatingActivities`，年初累計相減；FY2014–FY2015（與 FY2016 第一季）這個概念缺資料，改用 `NetCashProvidedByUsedInOperatingActivitiesContinuingOperations` |
| `capex` | `PaymentsToAcquirePropertyPlantAndEquipment`（Payments for acquisition of PP&E），年初累計相減；FY2013 以前用 `PaymentsToAcquireProductiveAssets`（重疊年度數字相同） |
| `dps` | `CommonStockDividendsPerShareDeclared`（宣告的每股股利），依申報日換算分割；第四季 XBRL 沒有單季值時用「全年 − 前三季」；4Q12 以前沒有配息，留空 |

### EPS 與股利的股票分割換算

XBRL 裡的每股數字是「申報當時」的股數基準，所以依 **申報日（filed）** 換算：

```
申報日 2014-06-09 以前              ÷ 28  （之後有 7 比 1 與 4 比 1 兩次分割）
2014-06-09 ─ 2020-08-30 申報        ÷ 4   （之後還有 4 比 1）
2020-08-31 以後申報                  不換算
```
小數保留 4 位。驗證方式：FY2012 全年 EPS 在 2014 年 10-K 是 6.31（已按 7 倍調整），÷4 ＝ 1.5775。

### 第四季推算
- 營收、毛利、營業利益、淨利：**全年 − 前三季**。已與 FY2021–FY2025 第四季新聞稿逐項核對一致。
- EPS：FY2020 以前取 XBRL 7–9 月單季值；FY2021 以後 XBRL 沒有單季值，取第四季財報新聞稿（4Q21 1.24、4Q22 1.29、4Q23 1.46、4Q24 0.97、4Q25 1.85）。

## 核對規則（`python3 tools/validate.py aapl`）

1. 毛利率、營業利益率與金額自洽；`fcf = ocf − capex`。
2. 四季加總 ＝ 全年（營收、毛利、營業利益、淨利、營業現金流、資本支出）。
3. `waterfall` 小計加總；第一列營收＝最新一季 `rev`。

**任何一項沒過就不發佈**，回到來源修資料，不要放寬核對。

## 更新步驟（每日排程「快報」步驟；補完、核對見 docs/SCHEDULE_PROMPT.md）

1. 查有沒有新財報：WebSearch「Apple reports {first/second/third/fourth} quarter results {年}」或 SEC 8-K 附件 99.1。**沒有新財報 → 跳到第 6 步。**
2. 讀 8-K 附件 99.1：損益表（Total net sales、Total cost of sales、Gross margin、R&D、SG&A、Operating income、Other income、Provision for income taxes、Net income、Diluted EPS）與現金流量表（Cash generated by operating activities、Payments for acquisition of PP&E，都是年初累計）。
3. 新增一季：第一～三季直接用單季數字；第四季（10 月底／11 月初公布）營收等用全年減前三季，EPS 用新聞稿單季值，並新增 `annual`（FY 全年數字取 10-K 或新聞稿的十二個月欄）。10-Q／10-K 的 XBRL 進 API 後用它核對上一季。
4. 更新 `waterfall`、`events`（下一個公布日；蘋果約在財報前一個月公告日期，公告後刪 `est`）、`milestones`（股利調整通常在 5 月的第二季財報）。`guidance` 保持空（新聞稿沒有數字財測）。
5. `python3 tools/validate.py aapl`；通過才繼續。
6. 查事件：股票分割、股利調整、重大產品、反壟斷與稅務判決（優先 8-K 與 apple.com/newsroom）。
7. `asOf` 改成今天（台北時間），`python3 tools/build.py`，commit、push。

## 資產負債表欄位（shOut、dilSh、cash、debt、buyback、equity、pretax、tax）
- 來源：SEC EDGAR XBRL companyconcept API，由 GitHub Actions 的 `bs-fetch` 產生提案（`data/bs-raw/<代號>.json`），`tools/bs_merge.py` 合併進資料檔。各欄位用哪些 XBRL 概念組成，寫在 `tools/bs_map.json`（必要項缺任何一項就整格填 null，不做部分加總）。
- 口徑：shOut＝期末在外流通股數（百萬股，分割後）；dilSh＝當季稀釋加權股數；cash＝現金及約當現金（不含有價證券）；debt＝有息負債（短期＋長期）；buyback＝當季股票買回金額（正數；年度累計相減得單季）；equity＝股東權益；pretax／tax＝稅前淨利／所得稅費用。
- 讀不到的季度為 null，原因彙整在 `notes.unavailable` 以「待確認：資產負債表欄位」開頭的幾行。新一季快報時，重跑 bs-fetch 後再 merge，或直接讀 10-Q／10-K 手動補。
- 合併時自動擋下：淨利÷稀釋股數與 EPS 對不上、股數差一個數量級、買回／負債／現金為負。
